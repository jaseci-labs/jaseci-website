# jaseci-org-jac

`jaseci.org` rewritten in [Jac](https://www.jaseci.org/). This is a full-stack
Jac `web-app`: the markdown content pipeline runs on the server codespace, the
UI compiles to a React bundle in the client codespace, and the RPC layer between
them is generated by the compiler.

It is a like-for-like port of the Next.js app in [`../jaseci-org`](../jaseci-org) —
same routes, same markup, same design tokens, same content.

## Running it

```bash
jac install          # python + npm dependencies
jac start --dev      # dev server with HMR
jac check .          # type-check the whole project
```

## Layout

```
main.jac                     entry point: registers endpoints, exports the client `app` shell
jac.toml                     project + dependency + serve config
assets/
  global.css                 Tailwind v4 theme + the ported SCSS layers
  images/                    everything that used to live in public/images
content/                     unchanged markdown (posts, authors, standalone pages)
server/
  content.jac                markdown/front-matter parsing, taxonomy, search, GitHub stats
lib/
  site.cl.jac                site config, menus, socials, slugify/humanize
  dom.cl.jac                 `any`-typed handles onto the browser DOM
components/
  *.cl.jac                   header, footer, logo, search, social, share, pagination, posts…
  landing/                   the four landing sections + the Journey timeline
  layouts/                   post / default / about / contact / author / 404 layouts
  views/                     the data-fetching shell behind each content route
pages/                       file-based routes (see below)
```

## How the port maps onto Jac

| Next.js | Jac |
|---|---|
| `lib/contentParser.js`, `taxonomyParser.js`, `jsonGenerator.js` | `server/content.jac`, parsed once at boot into module `glob`s |
| `app/api/github-stats/route.js` | `def:pub github_stats` in `server/content.jac` (same 5-minute cache) |
| `getStaticProps` / server components | `def:pub` endpoints + `sv import` RPC from `.cl.jac` components |
| `next-mdx-remote` + `remark-gfm` + `rehype-highlight` | Python-Markdown on the server, highlight.js at mount in `MDXContent` |
| `config/*.json` | `glob:pub` declarations in `lib/site.cl.jac` |
| `styles/*.scss` + `tailwind.config.js` | `assets/global.css` (`@theme` tokens, `@layer base/components/utilities`) |
| `next/image`, `next/link` | `<img>`, `Link` from `@jac/runtime` |
| `layouts/partials/SeoMeta.js` | `components/SeoMeta.cl.jac`, which writes the head imperatively |
| `public/images/**` | `assets/images/**`, served at `/assets/images/**` |

Front-matter `image:` paths are rewritten from `/images/...` to `/assets/images/...`
by `asset_path()` on the server, so `content/` stays byte-identical to the original.

### Behaviours kept deliberately

- Dates render through `America/New_York`, so an unquoted `2023-04-04` front-matter
  date still displays as `03 Apr 2023` — matching `date-fns-tz` on the old site.
- `slugify()` reproduces `github-slugger` exactly, including double hyphens
  (`"AI + Business"` → `ai--business`).
- The GA snippet loads `G-B7JPCXKQ36` while pageviews are sent to `G-V1KRXTNCWJ`,
  exactly as the two Next.js files had it.

## Conventions worth knowing

- Client modules that call the server use the explicit `.cl.jac` marker. With
  inferred placement, an `sv import` makes `jac start` auto-detect microservice
  mode and split `server/content.jac` into its own process.
- `glob`s and `obj`s imported across client modules need `:pub`, otherwise they
  are not emitted as JS exports.
- Browser globals go through `lib/dom.cl.jac`; `jac check` has no DOM stubs yet,
  so direct `document.*` member access fails type-checking.
